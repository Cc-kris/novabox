# Novabox V1.0 品牌、界面与交互设计规范

> 文档状态：UI / Brand Brief，供设计评审与后续实施使用  
> 创建日期：2026-10-28  
> 节点评分：2 / 2（方案阶段已含线框参考；实现后仍须真实截图验收）  
> 适用范围：桌面侧窗、独立窗口、工具 Schema 渲染页、草稿与设置

---

## 1. 品牌核心

Novabox 不是“另一个 AI 助手”，而是用户工作区里的**工具层**。品牌减少“模型正在施展魔法”的感觉，强调：

- **可靠**：每次执行有明确输入、结果和状态。
- **沉淀**：一次会话中的方法可以长期保留。
- **秩序**：工具、版本、来源和历史都有位置。
- **陪伴**：贴在熟悉的 Agent 旁，但不抢占工作焦点。
- **精巧**：像长期使用的桌面仪器，而不是营销网页。

### 1.1 名称与文案

标准写法：`Novabox`，不使用全大写，不拆成 `Nova Box`。

- 品牌主张：**让方法，成为工具。**
- 辅助文案：**聊出来的经验，留下来成为工具。**
- 英文辅助：**Turn know-how into tools.**
- 空库文案：**还没有工具，从一次有效的方法开始。**
- 创建入口：**从当前会话创建**
- Agent 状态：**已连接 Codex**
- 操作按钮：**运行、确认发布、删除草稿**

文案短、具体、说明下一步，不写“释放生产力”“一站式智能平台”等泛化口号。

### 1.2 品牌气质

| 应该是 | 不应该是 |
|---|---|
| 精密、克制、清晰 | 炫技、神秘、喧闹 |
| 有温度的工作工具 | 冷硬的开发者控制台 |
| 高密度但有呼吸 | 同权重卡片海洋 |
| 小而完整 | 把后台系统直接压窄 |
| 稳定、可信 | 到处发光、渐变、跳动 |

## 2. 标志与品牌资产

### 2.1 标志概念：开放的 N 型工具槽

主标由三个几何元素组成：

1. 两条垂直边界形成 `N` 的骨架。
2. 中间斜向连接表示“从对话到工具”的转化路径。
3. 右侧开口或独立短块表示工具从盒中取出、复用。

标志必须在 16px 应用图标、24px 顶栏和单色环境下可辨识。使用实心几何形，不使用细线渐变球体、立方体线框、机器人、魔法星或发光大脑。

### 2.2 标志组合

- 主组合：图形标 + `Novabox` 字标。
- 顶栏：图形标 + 字标，宽度不足时只保留图形标。
- 应用图标：石墨底、薄荷绿主体，不放文字。
- 单色版：托盘、文档、打印和状态栏。
- 安全空间：至少为标志主体宽度的 1/4。
- 最小尺寸：图形标 16px，完整组合建议不小于 96px 宽。

品牌图形可使用“工具槽、标签、连接路径、堆叠边缘”，只用于空态和关于页，不替代功能入口，不在卡片重复水印。

## 3. 视觉方向：Graphite & Mint

中文名：**石墨与薄荷**。

目标感受：像开发者桌面的精密工具册——深色机身、清晰刻度、少量状态灯、明确操作反馈。薄荷绿是功能性强调，不是整屏染色。

### 3.1 参考对象

以下来源作为组件与可访问性基准，不照搬皮肤：

- Radix UI Primitives：弹窗、菜单、焦点管理。https://www.radix-ui.com/primitives
- shadcn/ui：低噪声表单、空态、命令面板。https://ui.shadcn.com/
- Apple HIG：桌面窗口、用户掌控、清晰与反馈。https://developer.apple.com/design/human-interface-guidelines/
- Tremor：紧凑指标、结果和数据层级。https://tremor.so/

第 5、6 节的原创 ASCII 线框图是 Novabox 自身布局与交互参考。后续高保真设计须输出图片，线框不代替最终视觉验收。

### 3.2 去 AI 化硬约束

禁止紫蓝粉渐变、漂浮光斑、星空背景、多层玻璃拟态、装饰 emoji、超大 Hero、同尺寸浮起卡片海洋、无意义光晕、机器人或魔法图标。

图标统一使用 Lucide 风格线性图标或同规格 SVG，常规 16/18px、描边 1.75px；状态不能只依赖颜色。

### 4.4 字体与排版

- 中文/系统：`Inter`, `SF Pro Text`, `PingFang SC`, `Noto Sans CJK SC`, sans-serif。
- 字标：`Manrope` 600 或定制几何无衬线，只用于品牌，不大段使用。
- 数字与代码：`SF Mono`, `JetBrains Mono`, `Roboto Mono`, monospace。
- 页面主标题：18px / 26px，600。
- 分区标题：13px / 20px，600。
- 正文与输入：13px / 20px，400/500。
- 辅助信息：12px / 18px，400。
- 核心结果：24–28px / 32px，600，使用等宽数字。
- 不使用 10px 正文，不用全大写英文制造层级。

### 4.5 间距、圆角、边框与阴影

- 基础单位：4px。
- 间距：`4, 8, 12, 16, 20, 24, 32`。
- 页面水平边距：320px 宽时 12px；360px 及以上 16px。
- 控件圆角：6px；卡片/结果区：10px；胶囊状态：999px。
- 主按钮/输入高：36px；紧凑图标按钮：28/32px。
- 主内容尽量使用分隔线和背景层级，不默认浮起。
- 浮层阴影只用于菜单、弹窗和命令面板，不用于所有卡片。

### 4.6 动效

- Hover / 颜色：120ms，Fade。
- 按钮按下：80–120ms，无位移或仅 1px。
- 菜单 Pop in：140–180ms，`--ease-out`，无弹簧超射。
- 侧栏面板展开：180–240ms，Slide，`--ease-drawer`。
- 工具结果切换：160ms Cross-fade，避免布局跳动。
- 自动填参高亮：600ms 内消退，不循环闪烁。
- `prefers-reduced-motion` 下取消位移和弹簧，仅保留即时状态或淡入淡出。

## 5. 窗口框架与页面布局

### 5.1 总体框架

侧窗默认宽 360px，可在 320–480px 间调整；独立窗口可扩展至 720px 以上。侧窗只保留一个主内容列，不能再嵌套永久左右双栏。

```text
┌──────────────────────────────────────────────┐
│ 宿主 Codex / Claude Code                     │
│                                              │
│                                  ┌────────────────────────┐
│                                  │ N Novabox   ● Codex  ⋯ │ 44px 顶栏
│                                  ├────────────────────────┤
│                                  │ 工具  草稿  历史       │ 36px 导航
│                                  ├────────────────────────┤
│                                  │                        │
│                                  │      单一主内容列       │ 自适应滚动
│                                  │                        │
│                                  ├────────────────────────┤
│                                  │ 当前工具 / 主操作区     │ 按页面出现
│                                  └────────────────────────┘
                                   320–480px
```

- 顶栏包含品牌、宿主连接状态、窗口模式与更多菜单。
- 顶栏只显示一个连接状态，不堆叠多个彩色状态灯。
- 主导航最多显示“工具、草稿、历史”；设置和命令面板放顶栏。
- 内容区滚动，顶栏和主要操作保持可见。
- 窗口拖动与侧栏宽度拖拽区域分离，避免误触。

### 5.2 窗口模式入口

顶栏右侧菜单：

- 贴靠宿主 / 覆盖宿主 / 独立窗口。
- 收起侧栏。
- 重新选择宿主。
- 打开窗口诊断。

状态文案必须具体：`已贴靠 Codex`、`独立窗口`、`等待宿主恢复`。权限失败使用 warning，不伪装为已连接。

- 搜索框是唯一强输入区域。
- 空态保留创建与导入两个真实动作，不放装饰性大插画。

```text
│                            │

│                            │

│ ──────────────────────────│
```

```text
└────────────────────────────┘
```

发布前能看到工具将申请什么权限、测试是否真实通过、哪些来源仍需确认。失败测试不能被“发布”按钮绕过。

### 6.4 历史与设置

- 历史按时间倒序，每项显示工具、来源（手动/Codex/CC）、状态和时间。
- 点击进入只读运行快照；可“用此输入再次运行”。
- 设置按“窗口与宿主、Agent、外观、权限、数据”分组。
- 设置项采用标签在上/左、控制在下/右的窄窗适配，不压缩成密集三列表格。
- 危险操作放独立分区，默认不与普通设置混排。

### 6.5 宽度与独立窗口策略

| 宽度 | 布局 |
|---|---|
| 320–359px | 12px 页边距；隐藏字标；按钮必要时纵向排列 |
| 360–479px | 标准单列；16px 页边距 |
| 480–719px | 单列加宽；长表单可双列，但结果仍保持主次 |
| ≥720px 独立窗口 | 可显示左侧工具索引 + 右侧工具详情；非侧窗模式才启用 |

本项目没有 V1.0 移动端 App。移动/窄宽要求指 320px 桌面侧窗；不得声称已支持手机。

## 7. 组件规范

### 7.1 按钮

| 类型 | 用途 | 规格与状态 |
|---|---|---|
| Primary | 运行、确认发布 | accent 实底、accent.on 文字；每屏原则上一个 |
| Secondary | 复制结果、保存预设 | raised 表面、默认边框 |
| Ghost | 返回、展开、轻操作 | 透明背景，hover 才出现 subtle 表面 |
| Danger | 删除、停用 | 默认 danger 文字，确认弹窗中才可实底 |

所有按钮具备 hover、pressed、focus-visible、disabled、loading。Loading 保留原宽度并显示旋转进度图标和明确文字，不用全屏遮罩。禁用原因在相邻说明或 tooltip 中可获取。

### 7.2 输入与表单

- 标签在输入框上方，必填用文字和星号，错误不只用红框。
- 默认高 36px，长文本自适应但有最大高度。
- Focus 使用 2px accent 外环和清晰边框，不仅改变背景。
- 单位放控件内部右侧或独立选择器，不能挤占值的可读空间。
- 字段说明 12px，错误信息 12–13px，错误时保留原输入。
- 自动填参不覆盖用户已开始手动修改的字段；冲突时询问采用哪份值。
- 表格输入在窄窗下按行转卡片式编辑，不能横向挤压全部列。

### 7.3 工具条目与结果

- 工具条目最小高 64px，名称、用途、元数据三级排版。
- 当前工具使用左侧 2px accent 标记和弱背景，不使用大面积绿色。
- 结果区以分隔和排版形成层级，主要值使用等宽数字。
- 成功、警告、错误同时提供图标/文字，不只用绿黄红。
- 复制成功使用轻量 toast 和按钮文字短暂变化，1.5–2 秒后消失。

### 7.4 导航、菜单与弹窗

- 导航当前项使用文字权重、accent 下划线或浅底，不只改变颜色。
- 菜单 Pop in，从触发点附近展开；支持方向键、Esc、点击外部关闭。
- 弹窗只用于发布、危险操作和必须决策的权限确认。
- 弹窗打开后焦点进入，关闭后回到触发控件。
- Tooltip 只补充简短信息，不承载必要操作。
- 命令面板支持搜索工具、切换页面、重新贴靠、打开设置；结果按动作类型分组。

## 8. 关键交互流程

### 8.1 Agent 自动打开并执行只读工具

```text
Agent 搜索并选择工具
  → 本地校验参数
  → 同一内核执行
  → UI 收到 open/run 事件
  → 展开对应工具并填入参数
  → 新填字段短暂高亮
  → 结果区淡入，主要结果优先可见
```

- 若 Novabox 已可见，不抢夺键盘焦点；顶部显示“来自 Codex/CC”。
- 若 Novabox 已收起，按用户设置展开或只显示待查看徽标。
- 运行失败显示在工具页内，不弹通用错误对话框。
- 运行结果保留 `runId`，用户可回到历史快照。
- 若用户正在另一个工具中输入，不打断当前页面：只显示“有 1 个工具结果待查看”。

### 8.2 Agent 找到了工具但缺少参数

- 打开工具并填入已确认字段。
- 只读工具尚未执行，按钮显示“补全后运行”。
- 首个缺失字段获得清晰错误/待填状态，但不强制抢走 Agent 输入焦点。
- Agent 同时向用户提问；用户可在 Agent 或工具页补全，两端同步。
- 不用空值、零值或猜测值冒充已填写。

### 8.3 有副作用工具

- 页面先展示完整预览：将执行什么、影响哪里、使用哪些输入。
- 主按钮使用具体动作名，如“确认发布”，不使用含糊的“确定”。
- 用户确认后才执行；执行期间可显示进度，完成后保留结果和撤销入口（若确实支持）。
- 未经确认不得因 Agent 再次请求而自动跳过。

### 8.4 从会话创建工具

```text
收到草稿 → 右侧出现草稿预览
→ 用户查看用途、表单、权限、来源与测试
→ 信息不足则返回 Agent 修改
→ 校验和测试通过后“确认发布”
→ 工具进入工具库并可直接使用
```

草稿不是已安装工具。草稿页使用中性色“待确认”状态；验证失败不能被视觉弱化。

### 8.5 宿主和窗口状态

- 宿主移动/缩放：侧窗同步，不产生逐帧闪烁或可见拖拽残影。
- 宿主最小化：侧窗同步隐藏；恢复后回到原工具状态。
- 宿主关闭：显示“宿主已关闭”，可选择独立模式或退出。
- 宿主失去连接：不阻塞本地工具使用；顶部改为 warning 状态。
- 用户切换其他应用：Novabox 不继续悬浮遮挡。
- 覆盖模式明确标注“覆盖”，避免用户误以为拥有额外工作区。

## 9. 全状态与可访问性

### 9.1 必须设计的状态

| 状态 | 视觉与交互要求 |
|---|---|
| 空工具库 | 简短说明、创建草稿、导入工具；不只显示插画 |
| 搜索无结果 | 保留搜索词，提供清空和创建建议 |
| 首次载入 | 使用匹配真实结构的 skeleton，不无限 spinner |
| 刷新中 | 保留旧内容，局部显示更新状态 |
| 参数校验错误 | 字段级错误、页面摘要、焦点可定位 |
| 工具执行中 | 保留输入，按钮 loading，避免重复提交 |
| 执行成功 | 页面内显示结果和复制，不弹成功模态 |
| 执行失败 | 可理解原因、保留输入、重试和诊断入口 |
| 网络离线 | 本地工具继续可用；联网工具明确不可用原因 |
| 草稿待确认 | 中性状态、验证摘要、发布按钮按门禁启用 |
| 权限不足 | 说明具体系统权限和设置路径，不假装成功 |
| 宿主未连接 | 本地工具可用，提供重新选择与诊断 |
| 工具停用/规则过期 | 警告、来源与版本入口，不静默继续 |
| 数据为空或为零 | 区分“无数据”“零值”“未执行”，不统一显示 `--` |

### 9.2 键盘和屏幕阅读器

- 所有操作可通过键盘完成；Tab 顺序符合视觉顺序。
- Focus ring 在深色和浅色背景均清晰，不能被 `outline: none` 移除。
- 常用快捷键：命令面板、搜索、运行、返回、收起侧窗；允许用户查看和修改。
- 输入使用程序化标签；错误通过 `aria-describedby` 关联。
- 结果完成使用克制的 live region，不朗读整段页面。
- 图标按钮有可访问名称，装饰图标不重复朗读。
- 文字放大到 200% 时核心操作仍可使用，内容不裁切。
- 支持减少动效、高对比偏好和系统主题。

### 9.3 对比度底线

- 正文与关键控件文字达到 WCAG AA 4.5:1。
- 大字至少 3:1；控件边界与焦点指示至少 3:1。
- 已计算核心深色组合：主文字 16.99:1、次文字 7.79:1、accent 文字 10.96:1。
- 浅色主文字 15.14:1、次文字 6.46:1、accent 文字 5.32:1。
- 实现后须用最终实际背景和字号重新自动检测，不直接沿用设计稿结论。

## 10. 视觉禁忌与取舍

1. 禁止把界面做成“AI 聊天面板复制品”。
2. 禁止紫蓝渐变、霓虹泛光、玻璃拟态、泛光光斑作为默认风格。
3. 禁止 emoji 充当功能或状态图标。
4. 禁止每块内容都包卡片，避免卡片套卡片。
5. 禁止用无意义大数字、虚拟数据、假 AI 消息装饰主流程。
6. 禁止在 320–360px 窄窗使用永久双栏或密集多列表格。
7. 禁止为“高级感”降低文字对比度、隐藏焦点或缩小点击目标。
8. 禁止让 Agent 自动结果打断正在进行的用户输入。

取舍顺序固定为：**用户目标 > 可访问性 > 一致性 > 美感 > 开发便利**。

- [ ] 主页面一眼能区分工具名称、输入、主要操作和结果。

- [ ] 所有按钮、输入、标签、菜单、弹窗具备完整交互状态。
- [ ] 空/载入/空内容/错误/成功/禁用/权限/断线均有真实设计。

- [ ] 深浅主题与自动对比度检测通过。
- [ ] 键盘、焦点、屏幕阅读器与减少动效验证通过。

- [ ] 涉及真实 UI 实施后，按项目 SOP 完成文档/设计审核，不以构建通过代替视觉验收。

## 12. 目标视觉总结

Novabox 应当像一个**安静、精密、可持续扩展的工作仪器**：Graphite 深色结构提供秩序，Mint 只标记行动与活性，工具内容始终是主角。它的漂亮不依赖光效和渐变，而来自恰当的留白、稳定的排版、细腻的状态反馈和可靠的窗口联动。
